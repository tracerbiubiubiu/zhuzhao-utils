# 平台公共机制、协议与版本合同

> 2026-11-11 重规划。本页维护公共库边界与后续接入约束；不新增包/API、协议版本或发布 tag。排期、工作量与关闭证据唯一登记在主仓[规划总账](../../../zhuzhao/docs/review/planning-backlog.md)的 **R07 / P7**，相关调用/身份合同分别见 I01/I02。当前函数与线协议以[公共包](README.md)、[AK/SK](aksk.md)和[发布记录](../ops/releases.md)为准。

> **2026-11-13设计增量**：所有核心/可插拔业务能力的对外API与内部统一逻辑调用，语义权威为主仓[统一能力调用合同](../../../zhuzhao/docs/design/capability-invocation-contract.md)。共同词典可提前冻结，不表示已新增公共包或签名协议；新覆盖范围尚未复估，旧R07/I01等预算不自动扩展。当前只提交设计阶段快照，T0未启动。

## 1. 公共库只持有机制

本库继续承载无业务数据依赖的签名、令牌、错误/响应、日志、PG/Redis 构造和纯校验。角色/组织/资源策略、委托 grant、能力目录数据库、任务运行状态、工单/风险和 Agent 配置属于各业务属主，不迁入 utils。

跨仓确有相同消费者时，可以抽取窄的调用协议类型、签名、超时/错误约定或客户端机制；先有稳定合同和两个实际消费面，再决定是否新增公共包。不为了统一目录而制造 shared-core，不把模型厂商 SDK、MCP runtime、知识检索和工作流引擎全部放进本库。

企业专业平台供给已存在，具体 API/身份合同待验；本库不实现 SOC/SOAR/CMDB/TIP/知识或通用 Agent 的替代品。外部 Agent 和平台领域 Agent 都可消费相同公共机制，业务工具权限和领域 host 预算/确认仍由主仓负责。模型仅调用现有内网或获准外部 API，不涉及模型部署/训练。

## 2. 现有签名保证与不能推导的保证

`aksk/aksk.go` 的 `Sign` / `Verifier` 对既有 canonical 签名：method、path、body hash、时间、request-id、operator；query 不入签。时间窗不包含 nonce 单次消费；签名完整性不能推出业务执行一次、用户授权或 operator 获准代理该用户。

`aksk/gin.go` 的中间件与 `Transport` 处理现有普通请求；Reader/Streaming 的所有权、限体、时间窗、临时文件和错误分档见[协议](aksk.md)。真实可用接口由消费者的精确 pin 决定，不能据本仓 main 有文件推导旧 tag 都已包含。

`aksk/compat` 是独立存量协议，不覆盖 method/path、无 operator，不能作为新服务默认；其专用哨兵/失败适配与退役条件继续保留。新平台调用不应为了省事改用 compat，也不能单方面改既有 canonical 导致消费者断签。

## 3. R07：新调用、身份与协议兼容，P7 承接

I01/I02 先明确业务能力版本、输入输出、真实调用方、执行主体、on-behalf-of、批准引用、run/attempt 与关联标识的职责。utils 只在必要时提供可复用承载/签名机制；委托资格、实时权限交集、资源范围和危险动作确认由业务服务判定，不因签名字段存在自动放行。

新增安全相关字段必须明确是否被签名覆盖、来源是否可信、跨代理如何验证；不能把用户可填 JSON 字段当可信管理员身份。敏感参数和凭据用引用处理，响应/日志不回显秘密。需要 query 完整性、强防重放或更换算法时，必须先做版本化协议与双栈兼容设计，不直接修改默认算法。

R07 在 P7 开工前收口协议升级“实施/保留现状加限制/退出”决定与消费者矩阵；如有升级，制定固定迁移批、旧协议退出条件和回滚。没有相应需求则明确保留当前保证，不以模糊触发项永久悬置。协议形态和字段名称在该合同确定，本页不声称 v2 已实现。

MCP 与已有模型/Agent API 按各自官方协议适配，其授权、流式、取消与响应语义不自动等价于内部 AK/SK/业务信封。MCP 的 token audience/scope 或 provider 凭据由对应 adapter 校验，不能把浏览器 JWT 原样透传给任意下游。SDK 依赖应留实际消费者，只有真实通用机制才抽至 utils。

### 统一ID词典：静态能力与动态操作分开

| 标识 | 目标职责与库边界 |
|---|---|
| `capability_id` + `contract_version` | 静态能力及兼容合同身份；目录定义和版本政策归核心或扩展属主，不由utils建表 |
| OpenAPI `operationId` | API操作元数据别名；映射至能力，不作为效果幂等键 |
| `operation_id` | 动态业务效果的稳定去重身份；重投保留、同号异命令冲突，唯一凭证与效果事务由属主实现 |
| `invocation_id` | 一次逻辑调用；该调用的重投保留，独立调用可不同并关联同一operation；只读不必伪造效果操作 |
| `request_id` / `trace_id` | 一次HTTP请求与跨步骤追踪；不代替调用身份、业务去重或授权 |
| `delivery_id` | 一次投递尝试；与稳定业务效果及逻辑调用分开 |

这些是目标语义，不是新增线协议字段。当前`action/action_id`、`task_id/execution_id`和可能用于跨尝试关联的旧`request_id`均按现行消费者合同保留；升级须给显式别名/版本映射，不能通过全局rename改变历史数据或已有签名含义。纯格式校验、序列化和上下文携带可在真实复用后抽取；业务操作号何时生成、重放如何判同、保留多久及能否取消，仍由调用/领域服务决定。

### 公共信封不是共享领域模型

可复用的是窄的消息/调用元数据、ID承载、schema版本标记、签名与错误/客户端机制；`command`、`event`、`result`必须明确区分。command表达受权执行请求，event表达属主已提交事实，result关联某次调用/操作及其状态或凭证引用。事件出现、服务验签成功或结果通知送达都不产生额外执行权，也不等同业务效果成功。

工单字段、AL变更详情、风险评估、任务参数/业务结果、订阅过滤与映射、能力目录定义和授权/审批政策仍归核心或扩展；不能把这些payload、运行表和规则搬进utils来追求“格式统一”。相同元数据不要求所有消息使用同一payload，也不要求所有消息进入同一个队列。MCP等外部协议按其规定映射到共同语义，不把业务信封强套到JSON-RPC。

统一逻辑门面的进程内Service/Port、远程HTTP adapter及TR异步任务可以消费同一业务合同；utils不决定同步/异步、不路由业务、不重试未经属主声明可重试的动作。跨入口准入、调用链预算、防自触发/递归、事件风暴和多实例额度由平台/执行属主实现；库至多提供稳定合同下的纯客户端和校验机制，不能自建全局幂等库、通用事件中枢、授权引擎或shared-core。

实施前先核主仓定义和两个实际消费面的字段职责，再按R07/对应实施切片复估和决定提取。协议向量必须覆盖新增字段的签名/可信来源和旧消费者兼容；本页没有把当前`aksk`时间窗升级成nonce单次消费，也没有声明全能力API、调用SDK或MCP runtime已实现。

## 4. 版本、发布与消费者写主

utils 拥有公共 API/线协议和发布版本；消费者拥有自己的 go.mod/go.sum、调用接线与部署收据。能力目录/运行数据不能由一次库升级静默改变。主仓、taskrunner、activelist 可以按实际消费保持不同 pin，但必须在生态组合清单中说明兼容范围。

R07 核对稳定 tag、不可变 pseudo-version、源码提交、module sum 与实际接口；无业务收益不强迫所有仓同时升级。新正式 tag 只有在发布批实际完成后登记，合 main 不等于发版或生产承接。旧 pseudo-version 和承载 ref 在消费者迁移验证前保留，不清理为唯一可下载依据的历史。

新增公共 API 说明零值/上下文、body/reader 所有权、错误分类、密钥轮换、兼容与弃用；消费方以 `errors.Is` 等结构化机制判定，不依赖错误字符串。执行端通用客户端只有确需复用且合同稳定时才提取，不按旧“能力目录同批 SDK”设想预建空包。

## 5. 失败、幂等和扩展边界

验签失败必须在业务写前失败关闭；读体失败、超限、临时文件故障、context 取消和时间窗错误保持可区分，诊断留服务端。底层阻塞 reader 的打断仍由拥有者负责，库检查 context 不等于能取消任何 I/O。

库可以提供重试/超时的纯机制，但是否能重试、有无外部副作用、哪个调用是同一业务意图，由调用方决定。task_id/operation_id 及业务幂等凭证留业务/执行服务；不能在 utils 创建全局幂等数据库或通用运行状态机。流式请求也必须完整验签后才进入业务写。

扩展先选窄 Port/Adapter 和版本化合同，验证旧消费者，再提取共享机制；不要求业务服务依赖某个主仓本机路径，也不让工具库反向 import 业务模块。

## 6. 验收与落档

大量合成 mock、冻结线协议向量、受控时钟与故障 reader 长期保留。R07 覆盖空/非法头、规范化路径、字段篡改、时钟偏差、密钥轮换、窗口内重放的既有限制、普通/流式 body 错误、资源清理和 context；适合的解析器性质加入 fuzz，不能只测 happy path。

contract 验证新旧版本、服务端/客户端双向向量和实际消费者组合；从空 module cache 验证精确版本可下载，禁止用本机 replace/GOWORK 冒充真实发布。真实网络/密钥/专业服务验证由消费者单列，不在工具库测试发送真实请求或消耗模型额度。

本轮仅补文档，不关闭 R07、发布版本、改依赖或执行代码门禁。后续实现同步本页、[AK/SK 契约](aksk.md)、[发布记录](../ops/releases.md)、受影响消费者和主总账；发布、部署状态与测试通过分别留证。
